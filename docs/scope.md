# PowerPosition

## Idea
An AI-powered personal sports coach agent that gives competitive athletes — who don't have access to a real coach — personalized training plans, pre/post-match guidance, and a continuous improvement loop via Telegram and a web dashboard.

## Who It's For
Competitive ultimate frisbee players who self-train. They want coaching-level guidance (structured plans, mental prep, session feedback) but don't have access to or can't afford a dedicated coach. Accessibility is the core value proposition — a coach in your pocket, personalized to your game.

Long-term vision: sport-agnostic with a settings layer to configure sport. Demo focuses on ultimate frisbee.

## Inspiration & References
- **Athletica.ai** (https://athletica.ai/) — adaptive endurance plans that evolve based on training history. Closest to the continuous improvement loop concept.
- **FitnessAI** (https://www.fitnessai.com/) — automatic progression via feedback loop. Simple, executed well.
- **MongoDB LangGraph tutorial** (https://www.mongodb.com/docs/atlas/ai-integrations/langgraph/) — the architecture skeleton: MongoDBSaver checkpointer, MongoDBStore long-term memory, Atlas Vector Search for RAG.

Design energy: clean and functional. Dashboard clarity over visual flair.

## Goals
- Demonstrate a working agentic loop: athlete inputs data → agent generates plan → pre/post-match messaging → feedback fed back → plan improves
- Showcase MongoDB Atlas as the memory and retrieval backbone (not just a database)
- Win the MongoDB hackathon by making Atlas Vector Search, dual memory, and document storage all visible and purposeful in the demo
- Build something that feels genuinely useful to a real ultimate frisbee player

## What "Done" Looks Like
After 3-4 hours, the demo shows:
1. **Web app** with two screens — Calendar (session logs, upcoming games, weekly/monthly objectives) and Results/Plan (short-term, monthly, and long-term training plans generated by the agent)
2. **Telegram bot** you can talk to — log a session via Telegram and it appears in the web calendar
3. **Simulated pre-match message** — bot sends mental prep advice before a game
4. **Simulated post-match message** — bot collects feedback and feeds it into the session log
5. **Simulated continuous improvement** — agent references past sessions and updates the training plan
6. **Config screen** showing MCP connectors (Telegram, Calendar, Strava) — live for Telegram, others shown as configurable

MongoDB is doing real work: Vector Search on uploaded training material, MongoDBSaver for short-term conversation memory, MongoDBStore for long-term athlete memory, regular collections for session logs and plans.

## What's Explicitly Cut
- **Full Strava integration** — shown in config UI only, not live for demo. Too much OAuth/API surface for the time constraint.
- **Full Google Calendar sync** — shown in config, Telegram → Calendar flow is simulated. Real sync is post-hackathon.
- **Multi-sport configuration** — settings UI can show the concept, but all agent prompts and training material are ultimate frisbee only.
- **Automated pre/post-match triggers** — simulated manually for the demo. Real trigger logic (time-based, calendar event detection) is post-hackathon.
- **Real-time form feedback / video analysis** — out of scope entirely.

## Loose Implementation Notes
- **Stack**: Python backend, LangGraph agent, MongoDB Atlas (Vector Search + checkpointer + store), Telegram Bot API, web frontend (lightweight — likely Streamlit or simple Flask/React)
- **Agent tools**: web search (for training material lookup), RAG retriever (Atlas Vector Search on uploaded ultimate frisbee drills/strategy docs), session log read/write, memory save/retrieve
- **Memory**: MongoDBSaver for per-conversation short-term memory (thread_id = Telegram user), MongoDBStore for long-term athlete profile and key insights
- **LangGraph graph**: agent node → tools node (conditional) → back to agent → end. Standard ReAct pattern from the MongoDB tutorial, re-prompted for sports coaching.
- **Web app**: reads from MongoDB collections. Calendar view = session log documents. Results view = plan documents written by the agent.
